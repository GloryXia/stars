# 《光锥之外》首个开发切片 · 4 光年节点接入

首个开发切片从玩家调整半径开始。前沿抵达候选恒星后，节点在当地接入，指挥核收到回执后更新已确认节点数。M1 输出可复跑的时间线，M2 用 **Web-First 工程（TypeScript + Three.js/WebGL2 + HTML/CSS HUD）** 在桌面与移动浏览器中呈现结果。正式 Google 登录、海外 WSS 在线会话及万级空间分片在 M3 接入，M4 通过 Capacitor 封装 iOS/Android 辅端。[技术架构](ARCHITECTURE.md) · [GDD §9](../../DESIGN.md#implementation-and-acceptance)

## 1. 场景与时间基准

| 参数 | 首个场景取值 |

| 场景节点 | 静止的指挥核 A 在 `(0, 0, 0)`，静止的候选 B 在 `(4, 0, 0)`，坐标单位为光年。B 在公开星表中可定位，归属与接入结果由席位证据决定。 |

| 控制 | 指挥核在第 0 秒接受 `set_sphere_radius(4.00)`，同刻开始以 `0.10c` 扩张，并经直达链路发出接入授权。达到边界 `R_civ = 4.00` 时 B 满足包络覆盖条件。 |
| 链路 | 主场景中 A→B、B→A 各自可用。指挥端已有的两向链路报告在本场景结束前有效。发报、收报处理和节点部署时间在场景中均取零。 |
| 等待窗口 | 从指挥核创建请求时开始计时。场景统一在第 2754 现实秒超时，比主场景的预计回执（2634 现实秒）晚 120 现实秒。超时值由指挥端已知的场景条件预设。 |

## 2. M1 内核、输出与验收

### 2.1 执行顺序

1. **受理指令。** 校验纪元、请求 ID 与有限数值。按已知能级上限与摇篮下限求出接受半径，生成包络计划和指挥端的待确认记录。一个请求重试只受理一次。
2. **安排前沿与授权。** 前沿到达时间由包络计划求得。授权沿有向链路排程，收到后写入 B 的当地计划。前沿抵达与授权抵达都能重新检查接入前置条件，满足时进入部署；同刻具备接入资格的文明按稳定文明 ID 裁定。零部署时长在该时刻完成。当地提交前再次检查节点完好、空闲以及当地有效计划。
3. **发报与收报。** B 完成接入后，以当地采样时刻生成回执，按返程链路传播。A 收报后按来源版本与采样时刻更新已确认节点。重复报告只应用一次，迟到的旧采样保留历史。相同时间的回执和等待截止，场景先应用已抵达的回执，再处理超时。
4. **计算席位视图。** 以已确认节点计算节点数和冗余，以有效的有向路径计算已知可达远端数。视图保留请求状态和报告时间。合法的迟到回执可以把「超时 · 结果未确认」更新为已确认。[席位契约 · 网络视图](SEAT-CONTRACT.md#关键因果与网络摘要约束)

### 2.2 实现与交付

| 建议位置 | 交付物 |
| --- | --- |
| `packages/sim-core` | 双时钟换算、包络前沿、直达消息队列、节点当地接入、指挥端回执和快照恢复。 |
| `packages/contracts` | 版本化的半径指令、受理结果、席位视图和时间线帧校验。与 `SEAT-CONTRACT` 同义的节点、链路、时间及摘要字段保持单一真源命名。 |
| `scenarios/m1`、`apps/sim-cli` | 固定场景、时间断言、快照复跑和席位时间线导出。CLI 的开发诊断可查看权威事件，供客户端消费的文件只含席位视图。 |

时间线包含 `schema_version`、`epoch_id`、`seat_id`、`kappa_t`、指令受理前的 `initial_snapshot` 和按时间排序的 `frames`。每帧给出 `t_sim_s`、席位视图版本及完整快照，首帧是第 0 秒受理后的状态。快照最低包含 `r_civ`、`r_target`、`controlled_node_count`、`known_reachable_node_count`、`r_persist`、`nodes`、`links`、`pending_frontier_requests`。

公开星表坐标经席位坐标变换后作为独立输入。原型可用第 0 秒席位视图已披露的包络计划做半径插值，计划提供起止模拟时间与起止半径。到达下一帧时用权威半径校准。节点状态、标记与计数在对应证据帧生效。时间线格式供原型复跑，正式 HTTP/WSS 增量沿用同一席位视图契约。

### 2.3 自动化验收

| 场景 | 通过条件 |
| --- | --- |
| 主场景 | 单程光行 240 现实秒（`4.0 sim yr`）。B 在 2394 秒（`39.9 sim yr`）当地接入，A 在 2634 秒（`43.9 sim yr`）确认，前一秒（2633 秒）节点数仍为 1。 |
| 当地未接入 | 改变 B 的当地可用性，其余 A 端已知输入保持一致。与主场景比较，2634 秒前的席位字段与变更序列一致。当地结果没有送达时，超时（2754 秒）仍显示未确认。 |
| B 接入、回执缺失 | 在指挥端先前的报告仍有效时令返程不可用。B 保留当地归属，A 到截止时仍只确认 A。可单独注入合法迟到回执，检查状态从未确认更新为已确认。 |
| 授权迟到 | 延后发送授权，令前沿先到。B 在授权抵达后才接入，回执从新的当地时刻计算。 |
| 重试与乱序 | 相同请求 ID 重试只生成一次计划；同一回执重复投递只增加一次节点数；旧采样迟到后当前确认状态不回退。 |
| 保存后继续 | 在 2394 秒处理完当地接入、回执仍在途时保存。恢复后仅确认一次，2634 秒及后续席位帧与连续运行一致。 |

## 3. M2 Web-First 原型与移动端适配

### 3.1 两种视角的演示流程

1. Web-First 主场景（Three.js / WebGL2 + HTML/CSS HUD）载入公开星表和同一份合成席位时间线，初始显示摇篮 A、当前半径 0.01 光年以及已确认节点数 1。点击「扩张至 4 光年」触发场景中固定的受理记录。提供暂停、快进和重播，方便检查回执边界。
2. **天球仪**在 A 端画出公开星 B 的方向与标签。**三维星泡图**用公开坐标绘制 B、当前包络和目标半径参考轮廓。两视角共享一个席位状态，切换时保留播放位置和当前视角可呈现的选中节点。
3. 前沿到 B 后，两视角仍显示待确认，星图只按已披露证据绘制链路。成功回执抵达后，B 更新为己方已确认节点，两视角同步更新计数并可查看报告的采样和抵达时间。缺回执分支显示超时未确认。另用一条只含方向的合成观测验证二维方向可在天球仪选取，同时三维星泡图只对已披露坐标的对象开放拾取。

原型随包提供合成的席位时间线，方便 PC 浏览器与手机浏览器离线演示与回归对照。客户端原型验证按播放时间应用视图。实时信息隔离由 M3 海外服务端授权和空间分片投影验证。[技术架构 §3](ARCHITECTURE.md#3-游戏客户端与海外-web-first-交付链路)

### 3.2 移动端优先与 PC 操作

手机端以星图为主，常驻视角切换、当前与目标半径、确认节点数和主要操作。轻点节点后从底部展开详情，可查看接入状态及报告时间。底部操作和面板避开系统安全区。PC 窗口足够宽时，详情可停靠在侧栏，窄窗口沿用紧凑布局。布局切换保留播放位置、相机和当前可见选中项。

| 操作 | 手机触控 | PC 键鼠 |
| --- | --- | --- |
| 选星、查看详情 | 轻点标记，展开底部详情。 | 左键单击标记，展开详情。 |
| 查看不同方向 | 在天球仪单指拖动视线，在三维星泡图单指拖动旋转。 | 在星图区域按住左键拖动。 |
| 缩放三维星图 | 双指捏合，或点按 `+` / `−`。 | 星图内滚轮，或点击 `+` / `−`。 |
| 切换视角、扩张、控制播放 | 点按屏幕控件。 | 点击同一控件，或用 `Tab` 移动焦点，按 `Enter` 或空格激活。 |
| 关闭详情 | 点按关闭按钮。 | 点击关闭按钮，或在游戏获得焦点时按 `Esc`。 |

拖动超过移动阈值后由相机接管，抬手结束拖动。双指捏合取消本次点选，所有触点抬起后恢复点选。触摸或鼠标从控件、详情面板开始时由该区域处理，滚轮在详情面板内滚动内容。失焦、切后台或收到取消事件时清理进行中的手势。只有激活扩张控件才触发场景指令。

### 3.3 构建与验收

| 验收项 | 可交付结果 |
| --- | --- |
| **Web-First 构建与移动浏览** | 用 Vite + TypeScript + Three.js 构建静态 Web 产物并本地或海外静态托管预览。在至少一台 iOS Safari、一台 Android Chrome 及桌面 Chrome / Safari / Firefox 上，分别用触控与键鼠完成扩张、切视角、选星看详情、暂停与重播，跑通成功及超时分支，检查 `env(safe-area-inset-*)` 内控件可触达。 |
| 手势与控件 | 拖动或捏合结束后选中项保持原状，滚动详情时相机保持原位。切换视角、缩放和滚动均保持扩张指令提交次数不变。 |
| 前后台恢复 | 暂停或播放时切页签／后台，回到前台后从已保存的场景游标继续，当前半径、节点数和选中状态一致。 |
| **桌面响应式与键盘可达性** | 用鼠标单击、拖动和滚轮走完主流程，键盘焦点可见（`Tab` / `Enter` / `Space` / `Esc`）。宽屏分栏与竖屏单栏动态切换时保留播放位置与选中节点，同一时间戳席位状态完全一致。 |
| 性能记录 | 记录测试浏览器版本、WebGL2 渲染器与显卡／设备型号、首包 Brotli 压缩体积（预算 `< 1.5 MB`）、首次可交互时间、两视角帧耗时与 JS 堆内存峰值，作为发布预算基线。 |
| 复现材料 | 提供 CLI 场景运行说明、席位时间线、Vite 构建配置与跨端（桌面 + 移动浏览器）验收记录。 |

Web-First 构建产物于 M3 接入海外域名的 Google OIDC 登录与 Anycast WSS，于 M4 通过 **Capacitor 包装为 iOS / Android 辅端原生包**（复用全部游戏场景与席位契约，并在 iOS 端对等接入 `Sign in with Apple`）。

M3 复用 4 光年场景联调 **L1 确定性离线护航**与预留的 `ActorPrincipal` 指令总线：由 Web HUD 与服务端 3 槽白名单 L1 规则分别触发半径操作，验证待确认与回执一致；同时验证当 `external_agent` 尚未开放时网关正确拒绝并保留清晰扩展边界。[席位契约 §4](SEAT-CONTRACT.md#4-l1-离线确定性护航与-m4-外部-agent-扩展边界)
